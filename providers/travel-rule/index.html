What the Crypto Travel Rule Actually Requires

FATF Recommendation 16, the Travel Rule, requires a sending VASP to pass originator and beneficiary information to the receiving VASP before or during a virtual-asset transfer above the relevant threshold — not to screen the wallet itself, which is a separate crypto KYC function.

Core capabilities compliance teams typically require

  • IVMS101-formatted counterparty data exchange
  • VASP-to-VASP message routing without exposing data to non-VASP intermediaries
  • Counterparty due diligence before a transfer completes
  • Handling the "Sunrise Issue" — the gap where the receiving jurisdiction hasn't yet adopted equivalent rules

How this differs from Crypto KYC

Travel Rule software exchanges identity data between VASPs at transfer time; crypto KYC screens the wallet's own risk and onboarding history. Most platforms in this list also appear in Crypto KYC, since the same VASP often runs both.

Regulatory context

Key references: FATF Recommendation 16, the VASP (Virtual Asset Service Provider) designation, and the IVMS101 messaging standard used to format Travel Rule data.

Frequently asked questions

What is the crypto Travel Rule?

The Travel Rule, FATF Recommendation 16, requires a sending Virtual Asset Service Provider (VASP) to pass originator and beneficiary information to the receiving VASP before or during a transfer above the relevant threshold.

What's the difference between Travel Rule compliance and crypto KYC?

Travel Rule software exchanges identity data between VASPs at transfer time. Crypto KYC screens the wallet's own risk and onboarding history. Most VASPs run both, often from different vendors.

What is IVMS101?

IVMS101 is the data-model standard that defines how originator and beneficiary information is formatted for Travel Rule message exchange between VASPs.

What is the "Sunrise Issue"?

The Sunrise Issue refers to the compliance gap that arises when a sending VASP's jurisdiction has implemented Travel Rule requirements but the receiving jurisdiction has not yet adopted equivalent rules.

Do all crypto transfers require Travel Rule data?

No — most jurisdictions apply a minimum transfer threshold below which Travel Rule data exchange isn't required, though thresholds vary by country.

Can different Travel Rule protocols talk to each other?

Interoperability varies. Some providers support multiple protocols (such as TRP, OpenVASP, and Shyft) specifically to exchange data with VASPs that use a different underlying protocol.
